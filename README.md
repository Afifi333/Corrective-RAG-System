# Corrective RAG System (CRAG)

A complete Corrective Retrieval-Augmented Generation system, built entirely in Jupyter Notebooks for
the pipeline, with a standalone script for the deployed app. The system answers questions grounded in
your documents, but before answering, it grades the quality of the retrieved chunks — if they are weak
or irrelevant, it rewrites the question and retries retrieval. This significantly reduces hallucination.

The whole project runs **fully locally via [Ollama](https://ollama.com)** — no API key, no cost, and
inference itself runs on your machine.

## Architecture

```
Question ──► Retrieve top-k chunks (Chroma) ──► Grade each chunk (LLM judge: relevant / irrelevant)
                                                        │
                                    relevant ratio ≥ threshold?
                                    ┌───────── yes ─────────┐         no
                                    ▼                       ▼
                        Generate answer from        Rewrite query (LLM) ──► retrieve again
                        verified chunks only               (repeat up to max_rewrites)
                        + cite sources                            │
                                                        still no relevant chunks?
                                                                   ▼
                                                     Answer: "I don't have enough
                                                      verified information"
```

## Project requirements covered

- [x] Prepare and process documents (PDF / DOCX / TXT / CSV)
- [x] Ingestion pipeline: upload → extract → clean → split
- [x] Generate embeddings and store them in a vector database (ChromaDB)
- [x] Retrieve and evaluate the quality of retrieved chunks (LLM-as-judge)
- [x] Rewrite the query and re-retrieve if context is weak
- [x] Generate answers using verified context only (reduces hallucination)
- [x] Show answers with their sources
- [x] Handle questions that have no reliable answer
- [x] Deploy with Gradio — runnable directly from the command line

## Setup

1. Install [Ollama](https://ollama.com) (if not already installed), make sure it's running (it starts
   automatically after installation, or run `ollama serve` manually), and pull the two required models
   once:

   ```bash
   ollama pull nomic-embed-text
   ollama pull llama3.2:3b
   ```

2. Create a virtual environment and install the requirements:

   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. (Optional) If Ollama runs on a different address than the default, copy `.env.example` to `.env`
   and edit `OLLAMA_BASE_URL`. The default (`http://localhost:11434`) works out of the box in most
   cases.

4. (Optional) Add your own documents (PDF / DOCX / TXT / CSV) to `data/raw/`. The project works
   immediately with the sample documents already included.

5. Run the notebooks in order from `01` to `04` (each one has Markdown explaining every step):

   - **01_Data_Ingestion** — load, clean, and chunk the documents.
   - **02_Embeddings_VectorStore** — generate embeddings and store them in Chroma.
   - **03_Retrieval_Grading_Correction** — the heart of the system: retrieval, grading, query rewriting.
   - **04_Generation_Answer_Pipeline** — generate the final answer with sources, and handle the
     "no answer" case.

   Each notebook is self-contained and can be run on its own after the previous one has run at least
   once (each step persists its results to disk: `chunks.json`, then the Chroma database).

6. Once the vector store exists (step 5 above, notebook 02 at minimum), launch the interactive app
   directly from the command line:

   ```bash
   python app.py
   ```

   Then open the printed local URL (usually `http://127.0.0.1:7860`) in your browser.
